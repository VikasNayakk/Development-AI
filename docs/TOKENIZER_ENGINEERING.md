# Experimental byte-level BPE tokenizer

## Status and compatibility boundary

The core.bpe_tokenizer.ByteLevelBPETokenizer is an experimental, project-owned tokenizer implementation. It is deliberately separate from core.tokenizer.ByteTokenizer.

- The existing utf8-byte-v1 tokenizer remains the production tokenizer.
- ModelConfig.vocab_size remains 256.
- Training, generation, evaluation and checkpoint formats are unchanged.
- No existing checkpoint is migrated or rewritten by this experiment.
- The BPE implementation uses no pretrained vocabulary, external tokenizer package, hosted API or model runtime.

Do not connect this tokenizer to model training until benchmark results, artifact validation and a versioned checkpoint migration plan have been reviewed.

## Design

The vocabulary starts with all 256 possible UTF-8 byte values. Training learns adjacent-token merges from explicitly supplied UTF-8 text.

- Each document is processed as a separate sequence; merges cannot cross document boundaries.
- At each merge round, the most frequent pair is selected.
- Equal-frequency pairs use lexicographic token-ID order for deterministic tie-breaking.
- Occurrences are merged left-to-right without overlap.
- Merge order is stored as token IDs; new IDs are assigned sequentially from 256.
- Encoding applies learned merge ranks in rank order.
- Decoding expands token IDs back to bytes and decodes UTF-8 with replacement for invalid generated byte sequences.

The trainer and encoder use linked-node arrays and a priority queue to avoid rescanning the entire corpus for every merge. The current trainer is still in-memory and uses Python data structures; it is experimental, not yet optimized for large corpora.

## Train and benchmark

Use a reviewed, rights-cleared UTF-8 text corpus. The CLI defaults to target vocabulary sizes 2,048, 4,096 and 8,192 and has a conservative 50,000-byte input limit.

~~~bash
python -m core.benchmark_tokenizer \
  --data data/processed/train.txt \
  --output-dir artifacts/tokenizer-benchmarks \
  --vocab-sizes 2048 4096 8192
~~~

The command writes one integrity-checked tokenizer JSON artifact per target vocabulary and a benchmark-report.json.

The report includes actual vocabulary size, merge count, byte-token count, BPE token count, token reduction, compression ratio, training time and encoding throughput. Results are corpus-specific. Token reduction is not a measure of language quality, reasoning, or downstream model quality.

To use a larger corpus, first review available memory and deliberately raise --max-training-bytes. Do not point the experiment at private or unreviewed data.

## Artifact integrity

Artifacts contain a schema version, tokenizer identifier, base vocabulary size, final vocabulary size, ordered merges and a SHA-256 digest over canonical JSON metadata. Loading validates the schema, merge references, vocabulary size and digest.

SHA-256 detects accidental corruption; it is not a digital signature and does not establish the provenance or licensing of the training corpus.

## Acceptance gates before model integration

1. Run the full test suite and review the CI logs.
2. Benchmark all target vocabulary sizes on the same representative, rights-cleared corpus.
3. Check exact round trips for Hindi/Devanagari, English, numbers, punctuation, emoji and mixed Unicode.
4. Review artifact determinism, integrity failures and malformed inputs.
5. Compare token reduction and tokenizer throughput across corpora; record corpus hashes and settings.
6. Define checkpoint metadata, tokenizer artifact distribution, vocabulary-size model changes and old-checkpoint compatibility before changing the production pipeline.
7. Only then consider a separately reviewed migration PR.
